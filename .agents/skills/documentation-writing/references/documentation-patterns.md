# Documentation patterns

Read this reference when title examples or a detailed page scaffold help the requested document. These structures are illustrative. Omit, combine, or reorder sections to serve the audience and task, including a requested mixed document.

## Tutorials

Possible titles: Build your first X; Create Y from scratch; Get started with Z by building A.

A useful progression:

1. What the reader will accomplish and who the tutorial serves
2. Prerequisites and setup
3. Numbered steps with expected results and what to notice
4. Final outcome
5. Next steps and links to deeper material

## How-to guides

Possible titles: How to configure X; How to deploy Y to Z; How to troubleshoot A when B happens.

A useful progression:

1. Goal or problem and when the guide applies
2. Assumptions and prerequisites
3. Recommended path, steps, and decision points
4. Verification or expected result
5. Related reference and explanation

## Reference

Possible titles: Configuration options; API endpoints; CLI flags; `POST /users`; `deploy` command.

Choose a consistent schema that matches the documented object. Include applicable, known fields; mark missing information rather than filling gaps with invented details.

- **APIs:** operation, summary, method and endpoint, authentication, parameters, request body, responses, errors, examples, limits, related pages
- **Commands:** command, syntax, options and flags, defaults, exit codes, examples, related commands
- **Configuration:** field name, type, default, allowed values, description, examples, warnings

## Explanation

Possible titles: How X works; Understanding Y; Why Z is designed this way; Authentication vs authorization.

A useful progression:

1. Topic or question and context
2. Core idea and mechanism
3. Rationale and constraints
4. Relevant history, alternatives, and tradeoffs
5. Implications and related concepts
